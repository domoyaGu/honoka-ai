# 职业规划落盘（苏州 · 8 年前端 → AI 全栈）

> 供换机 `git pull` 后续规划。结论来自对话对齐；与 `job-gap-checklist.md`（JD 缺口）互补：本文偏**角色阶梯 / 学习主线 / 投递 ROI / 本仓优先序**。

## A. 渐进角色阶梯（一行）

**Frontend+一点后端 → +嵌浅 AI（助手/浅 RAG）= 全栈（业务+AI） → +真流式+生产 RAG+评测 = 大模型应用/AI 全栈 → +工具循环+护栏/HITL+状态编排 = Agent 应用（工程）**

| 台阶 | 日常例子（口述用） |
|------|-------------------|
| 业务全栈 + 浅 AI | 采购单 CRUD +「制度/报销问答」嵌入业务页 |
| 大模型应用 / AI 全栈 | 手册知识库：真流式回答、引用、准确率/评测可讲 |
| Agent 应用（工程） | 查单 → 草稿 → 审批（HITL）→ 建工单；有工具白名单与轨迹 |

## B. 学习主线（共用再分支）

```
共用：真流式 → 真 RAG → 薄后端(DB/JWT)
├ 投 A 加深：混合检索 / Rerank / 评测 / 成本
├ 投 B 加深：Tool 循环 / 护栏 / 状态图 / 轨迹 UI
└ 投 C 加深：业务模块与 DB，AI 保持「嵌得进」
```

**当前建议**：主学到「大模型应用」；Agent 作作品加厚；业务全栈作保底投递。

## C. 苏州岗位 ROI（去水分后）

来源：Boss / 智联 / 51job / 猎聘。过滤：HR 低活跃、90 天陈旧、标题党（销售/ERP 冒充 AI）、假 AI JD。

| 方向 | 有效需求（苏州去水分） | 策略 |
|------|------------------------|------|
| ① 业务全栈 + 浅 AI | ★★★★★ | 保底最优 |
| ② 大模型应用 / AI 全栈 | ★★★☆（挂牌多水分大） | 溢价较好 → **主攻 + 验活** |
| ③ Agent 工程 | 苏州有效稀；一线高薪多在别处 | 不当唯一岗名 |

**性价比（苏州去水分）**：② ≈ ① > ③

**投递验活清单**

- 今日 / 刚刚活跃优先
- 读完整 JD，剔标题党与「贴 AI 关键词」假岗
- 猎聘「久未更新」慎投

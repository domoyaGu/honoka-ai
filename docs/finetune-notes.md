# 微调笔记（Honoka）

> 目标：会判断「该不该微调」、会准备数据、能跑通一条 LoRA 实验并写回结论。  
> 训练多在仓外 GPU/云；本文件是清单与结论坑位。

## 1. 先决策

| 手段 | 适合 | 不适合 |
|------|------|--------|
| Prompt | 格式、语气 | 大量私有事实 |
| RAG | 常变文档（本仓主路径） | 极稳文风模板 |
| 工具 | 实时行动 | 纯背诵 |
| SFT / LoRA | 稳定口吻、固定 JSON 骨架、缩短提示 | 事实天天变 |

## 2. 知识点

- 数据：指令对、清洗、去毒、train/val/test。  
- SFT；LoRA / QLoRA；全参边界。  
- 对齐概念：RLHF、DPO（数据形态：chosen/rejected）。  
- 评测：同一 `fixtures` 上对比 基座 vs 微调 vs RAG。  
- 合规：仅用授权语料。

## 3. 建议最小实验（仓外）

1. 任务：统一「带 [1][2] 引用的简答」风格（50～200 条）。  
2. 基座：小模型（如 1.5B～7B）+ LoRA。  
3. 对比：强 Prompt+RAG（本仓） vs 微调模型无 RAG。  
4. 记录：数据量、步数、评测分、灾难性遗忘现象 → 写在下方「实验记录」。
